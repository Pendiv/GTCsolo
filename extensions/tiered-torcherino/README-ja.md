# GT Tier別Torcherino

自作部分はMIT。パックに入っているTorcherino 20.0.0の画面・設定通信・加速処理を実行時に利用する独立連携MOD。GTCEuのJava APIへ依存せず、GT1.6.4用の開発環境とGT7.2.0のATM9へ同じ機能を持ち込む。見た目にはユーザー制作の電圧別テクスチャを使う。

## 加速力

| Tier | 加速力 | Tier | 加速力 |
|---|---:|---|---:|
| LV | 2 | UV | 19 |
| MV | 3 | UHV | 23 |
| HV | 5 | UEV | 29 |
| EV | 7 | UIV | 31 |
| IV | 11 | UXV | 37 |
| LuV | 13 | OpV | 41 |
| ZPM | 17 | MAX | 43 |

基準はtick付与100%、表示範囲1×1×1。1点を速度＋100%、またはどれか1軸の半径＋1（表示幅＋2）に割り振る。共通予算なので、各パラメーターの上限を同時には使えない。

全Tier共通で表示範囲の上限は**9×3×9（X×Y×Z）**。半径ではX/Zが4、Yが1。加速力が余っていても範囲はこれ以上広がらない。9×3×9には9点を使い、残りは速度へ割り振れる。旧版で広げすぎた保存値は読込時にこの上限へ縮める。

`使用点 = (tick付与率 / 100 − 1) + (幅X − 1) / 2 + (幅Y − 1) / 2 + (幅Z − 1) / 2`

LV=2の例：

- 100%・3×3×1 → 2点。
- 200%・1×1×3 → 2点。
- 100%・1×1×5 → 2点。
- 200%・3×3×1 → 3点なので不可。

Torcherinoを中心にした範囲なので、1×1×1のままでは周囲のブロックを対象にしない。UIには元の4スライダーとレッドストーン設定を表示し、使用加速力の行を追加する。ポイント不足では操作中のスライダーだけを上限へ戻す。他へ割り当てた点は奪わない。

サーバーは設定パケットを検査し、不正な変更を拒否する。過大なNBTは読込時に正規化し、加速tick前にも検査する。セーブには元のTorcherino形式を使う。設定範囲・速度・レッドストーン動作・所有者・ブラックリスト等の加速本体は元MODが担当する。

`config/gtcsolo_torcherino.toml`のpower節でTierごとの値を変更できる。再起動で反映し、Tier情報はTorcherinoの既存同期機能でクライアントへ送る。

## 追加品と導入

LV～MAXの14段階それぞれに、加速の松明・加速のランタン・加速のジャック・オ・ランタンを追加する（42アイテム）。IDは`gtcsolo_torcherino:lv_torcherino`、`lv_lanterino`、`lv_jack_o_lanterino`等。同じ電圧の3形状は加速力も設定制限も同じ。松明は床置き・壁掛け、ランタンは床置き・吊り下げ、かぼちゃは4方向に対応する。ランタンのブロック画像はアニメーション付き。松明の手持ちは設置用モデルではなく、柄を持つアイテムモデルを使う。

専用クリエイティブタブから取得できる。製造レシピと、元のTorcherino品の置換は今回指定されていないため追加していない。gtcsolo本体の湧き潰し用電圧松明とは別のアイテム。

全形状をTorcherino標準の加速ブラックリストへ登録する。自身や他の加速灯を相互加速して再帰しないために必要な登録。

通常のATG配布では、この追加部分を工業本体の`gtcsolo-<version>.jar`へJar-in-Jarで同梱する。追加部分を別JARとしてmodsへ置く必要はない。保存ID・設定ファイル・クリエイティブタブは従来どおりで、MOD一覧には同梱モジュールも表示される。元のTorcherino 20.0.0は引き続き別途ロードする。

親Gradleの`:build`は追加部分もソースからビルドして同梱する。配布用は従来の`build/libs/gtcsolo-<version>.jar`で、同梱前の中間JARは`build/intermediates/slim/`。通常の開発起動も追加部分のsourceSetを読み込むため、古い`run/mods/gtcsolo-tiered-torcherino-*-dev.jar`は同時に入れない。

ATM9など工業本体を入れない環境向けには、従来の独立本番JARも作成できる。その場合だけ本番JARをmodsへ置く。独立検証用の開発環境ではdev JARを使用できるが、本番/devを同じ環境へ重複配置しない。

## ビルドと検査

JDK17を使い、TorcherinoのForge 1.20.1用20.0.0 JARを`libs/Torcherino-forge-1.20.1-20.0.0.jar`へ置いて、`.\gradlew.bat build devJar`を実行する。元JARの配布元は https://www.curseforge.com/minecraft/mc-mods/torcherino/files/4722725 。

`budgetTest`は共通予算・LV境界・負数/整数overflow・再配分・改ざん状態の正規化を検査する。`runServer`は専用smoke MODを一時ロードし、独立ワールドで実Torcherinoの設定受付・保存・全形状のブロックエンティティ型・tick前の防御・有効状態の加速を検査して停止する。かまどへ追加2tickが渡り、自己再帰しないことも検査する。smokeクラスは配布JARへ含めない。

`runClient -PsmokeClient`はローカルのSynapse検査JARを用いた任意の画面検査用。通常の利用にはSynapse不要。

`python tools/verify_resources.py`で全42アイテムのモデル参照・ドロップ・日英名と、ユーザー制作PNG84枚・アニメmetadata14件を確認する。制作元からの再取り込みは`python tools/import_artwork.py <松明のoutputディレクトリ> <ランタン・かぼちゃのoutputディレクトリ>`。元のピクセルとmetadataは改変せずコピーする。

実操作での確認項目：

- 松明の柄を持つ位置、壁掛け4方向、ランタンの吊り下げとアニメ、かぼちゃの向き・破壊時のドロップ。
- LVで100%・3×3×1を設定し、さらに速度を上げようとしても2点を超えないこと。片方の範囲を戻すと200%・3×1×1へ振り替えられること。
- MVで100%・3×3×3を設定し、画面を閉じて開き直しても値が残ること。
- レッドストーン制御で加速を切り替えられること。通常のTorcherinoの設定制限が変わっていないこと。
